# ADR-012: Resume File Storage and Secure Access

- **Status**: Proposed
- **Date**: 2026-11-20
- **Authors**: Technical Lead, Architecture Engineer

---

## 1. Context
Candidates upload personal resumes in PDF/DOCX formats. These documents contain personal contact information, academic background, and employment records. Resumes must be stored securely, protected against unauthorized access, and made accessible to parsing workers and candidate owners without exposing public URLs. We must evaluate candidate object storage options without prematurely locking into a single provider.

## 2. Decision (Investigation Underway)
We propose to adopt **Private Object Storage with Pre-Signed Access Controls**, while keeping the specific storage provider under active evaluation between **Supabase Storage** and **Amazon S3**.

Regardless of provider, the following architectural invariants are enforced:
1. Public read access to resume storage buckets is strictly disabled.
2. Candidate objects are partitioned: `candidates/{user_id}/{resume_id}.pdf`.
3. Candidate uploads and downloads use time-limited (e.g. 15-minute) pre-signed URLs generated by the backend only after validating the caller's Supabase Auth token and user ownership (`user_id == current_user.id`).

## 3. Alternatives & Trade-Offs Considered

### Option A: Supabase Storage
- **Pros**:
  - Integrated directly with the Supabase ecosystem and Auth service.
  - Allows leveraging Supabase storage Row-Level Security (RLS) policies tied directly to `auth.uid()`.
  - Consolidated platform footprint with unified developer billing/management.
- **Cons**:
  - Storage is hosted outside AWS `ap-south-1`, meaning Lambda workers in AWS must transfer resume files over external HTTPS.
  - Included free tier is limited to 1 GB storage and 2 GB bandwidth monthly, after which paid tier upgrades apply.

### Option B: Amazon S3 (AWS `ap-south-1`)
- **Pros**:
  - Co-located in the same AWS region (`ap-south-1`) as the FastAPI API Lambda and SQS Worker Lambda, ensuring minimal latency and zero intra-region data egress costs.
  - Granular AWS IAM execution roles and VPC endpoint integration.
  - Mature S3 object lifecycle rules for automated object versioning and orphan cleanup.
- **Cons**:
  - Separate infrastructure component managed via Terraform outside Supabase.
  - Requires implementing custom pre-signed URL token generation via boto3 in FastAPI.

## 4. Consequences
- **Positive**: Protects candidate privacy; prevents database bloat; offloads file transfer bandwidth from the API Lambda.
- **Negative**: Final implementation of the storage client is deferred until the provider decision is approved by the Technical Lead.

## 5. Risks
- Delay in selecting a provider could impact Subphase 02/03. Mitigated by abstracting resume storage interactions behind a generic `StorageService` protocol in the backend.
